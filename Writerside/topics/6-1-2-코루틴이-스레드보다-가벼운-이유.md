# 6.1.2 코루틴이 스레드보다 가벼운 이유

코루틴이 “스레드보다 가볍지만, 스레드처럼 동작할 수 있다”고 하는 이유를 이해하려면 다음과 같은 원리를 살펴보아야 합니다.

## 1. 사용자 레벨(Userspace)에서의 스케줄링

- **스레드**는 운영체제(OS)에서 직접 관리되고 스케줄링됩니다. 따라서 스레드를 하나 만들 때마다 OS가 할당해야 하는 자원(스택, OS 스레드 컨트롤 블록 등)이 필요하고, 스레드 사이를 전환할 때도 OS 단에서 문맥 교환(Context Switch)이 일어납니다.
- **코루틴**은 운영체제가 아닌 **사용자 레벨**에서 스케줄링합니다. 즉, 코틀린 런타임(또는 코틀린 표준 라이브러리)이 “현재 어느 코루틴을 실행할지, 어디서 중단하고 재개할지”를 자체적으로 관리합니다.
- 이 덕분에 OS가 직접 개입하지 않고도 실행 흐름을 전환할 수 있어, 스레드를 만들거나 없앨 때 발생하는 무거운 오버헤드가 크게 줄어듭니다.

## 2. suspend 키워드와 상태 기계(State Machine)

- 코루틴을 정의할 때 사용하는 `suspend` 함수는, 내부적으로 상태 기계(state machine) 형태로 컴파일됩니다.
- “여기서 잠깐 중단(suspension point)했다가 다시 돌아오면, 이전 상태를 어떻게 복원할지” 등에 대한 로직을 **컴파일 시점**에 미리 만들어 두는 것입니다.
- 덕분에 **코루틴**은 필요한 시점에 다른 코루틴으로 자연스럽게 제어 흐름을 넘길 수 있고, 다시 돌아올 때도 이어서 작업을 할 수 있습니다.

## 3. 하나의 스레드 안에 여러 코루틴이 공유

- 일반적으로 안드로이드나 서버 환경에서는 ‘스레드 풀(Thread Pool)’이 있고, 이 스레드 풀을 통해 여러 코루틴을 병렬 혹은 동시적으로 동작시킵니다.
- 예를 들어, 코틀린에서는 `Dispatchers.IO`가 I/O 작업에 최적화된 스레드 풀을 사용하고, 여러 코루틴이 이 풀에 있는 스레드들을 돌아가면서 사용합니다.
- 코루틴 자체는 독자적인 실행 맥락(Context)을 갖지만, 실제 물리적 스레드는 공유하고 있기 때문에 OS 입장에서는 “스레드 수가 크게 늘어나지 않고, 기존 스레드에서 여러 코루틴이 번갈아가며 동작하는” 구조가 됩니다.

## 4. 필요할 때만 CPU 자원을 독점하고, 중단 가능

- 코루틴은 “실행 중”일 때만 CPU를 점유하고, 네트워크 I/O나 DB 작업처럼 대기 시간이 필요한 경우 `suspend` 지점에서 중단됩니다.
- 코루틴이 중단된 동안에는 다른 코루틴들이 해당 스레드를 활용해 작업을 진행할 수 있게 됩니다(= 협력적 멀티태스킹 느낌).
- 스레드는 한 번 할당하면 계속 해당 스레드가 점유되어야 하지만, 코루틴은 스레드가 필요없는 상태(중단 상태)일 때 다른 코루틴들이 그 스레드를 활용할 수 있으므로, 자원 효율이 뛰어납니다.

## 5. 문맥 전환(Context Switch)의 경량화

- OS 레벨 스레드끼리는 문맥 전환 시 레지스터, 스택, 프로세스 컨텍스트 등을 교체해야 하므로 오버헤드가 큽니다.
- 코루틴끼리는 “사용자 레벨”에서 필요한 최소한의 데이터만 교체하고, 상태 기계 로직에 따라 진행하므로 **경량 문맥 전환**이 가능해집니다.
- 결과적으로 같은 프로세스/스레드 내에서 코루틴 전환이 빠르게 일어납니다.

## 종합 정리

1. **사용자 레벨 스케줄링**: 운영체제가 아닌 코틀린 런타임에서 코루틴을 직접 관리하므로, 스레드 생성·종료·전환에 비해 훨씬 가볍습니다.
2. **상태 기계로 컴파일**: `suspend` 함수가 상태 기계 형태로 변환되어, 중단 후 재개 시점이 관리됩니다.
3. **하나의 스레드에서 여러 코루틴을 공유**: 스레드 풀이 코루틴을 효율적으로 분배·재사용할 수 있습니다.
4. **협력적 멀티태스킹 구조**: I/O나 기다림이 필요한 순간에 코루틴이 스스로 중단(suspend)하고, 다른 코루틴이 그 자원을 사용하게 합니다.
5. **경량 문맥 전환**: OS 스레드를 바꿔 끼우는 것이 아니라, 사용자 레벨에서 최소한의 정보만 교환하기 때문에 오버헤드가 적습니다.

이러한 원리 덕분에 코루틴은 “스레드보다 훨씬 가벼운 단위”이면서도 “스레드처럼 독립적인 실행 흐름”을 가질 수 있습니다.
