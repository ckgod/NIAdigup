# 6.1.1 동시성과 비동기

## 1. 동시성(Concurrency)이란?

**동시성**은 여러 작업(또는 프로세스, 스레드)이 서로 번갈아가며 실행되면서, **‘마치 동시에 실행되는 것처럼 보이는’** 상태 또는 그 개념을 말합니다.

- 예를 들어, 프로세서가 매우 빠르게 작업을 전환(Scheduling)하며 동작하면, 겉보기에는 여러 작업이 동시에 수행되는 것처럼 느껴집니다.
- 실제로 하나의 CPU 코어에서는 한 순간에 하나의 작업만 수행하지만, 빠른 전환을 통해 “동시에” 처리되는 듯한 효과를 만들어냅니다.

### 1.1 단일 코어에서의 동시성

- 단일 코어에서는 한 번에 한 가지 작업만이 CPU 자원을 사용할 수 있습니다.
- 하지만 **시간 분할**을 통해 CPU가 일을 조금씩 번갈아 처리하면서, 각 작업이 모두 실행되는 것처럼 보이게 됩니다.

### 1.2 멀티 코어에서의 동시성

- 멀티 코어 환경에서는 실제로 여러 코어가 병렬적으로 작업을 처리할 수 있습니다.
- 여러 코어가 각각 다른 작업을 동시에 실행하므로, 진정한 의미의 **병렬성(Parallelism)** 도 가능해집니다.
- 하지만 “동시성”이라는 개념은 꼭 멀티 코어가 아니더라도, 여러 작업이 *겹쳐서* 혹은 *섞여서* 수행되는 모든 상황을 포괄합니다.

> **정리**  
> - 동시성은 “여러 일을 나란히 진행하고 있다”는 개념을 의미합니다.  
> - 실제로는 시분할이든, 병렬이든, 결과적으로 동시에 처리되는 것처럼 보이거나 실제로 처리되는 상황을 모두 아우릅니다.

## 2. 비동기(Asynchronous)란?

**비동기**는 **“특정 작업이 완료될 때까지 기다리지 않고, 그 사이에 다른 작업을 할 수 있다”** 는 방식 또는 개념입니다.

- 반대 개념은 **동기(Synchronous)** 입니다. 동기 방식에서는 A 작업이 끝나야 B 작업을 시작할 수 있습니다.
- 비동기 방식에서는 A 작업이 완료되는 것을 기다리지 않고, B 작업을 먼저 처리할 수 있습니다. A가 끝나면 그때 별도의 알림(콜백, 이벤트 등)을 통해 결과를 알려줍니다.

### 2.1 왜 비동기가 필요할까?

- 네트워크 요청, 파일 I/O, DB 쿼리 등은 상대적으로 시간이 오래 걸리는 작업입니다.  
- 동기 방식으로 처리하면, 해당 작업이 완료될 때까지 메인 흐름이 멈춰 있어야 합니다(블로킹).
- 비동기를 사용하면, 그 작업이 끝날 때까지 메인 흐름이 차단되지 않고 다른 일을 계속할 수 있어, 프로그램 전체가 멈추지 않고 부드럽게 동작합니다.

### 2.2 비동기 처리 예시

```kotlin
// 동기 방식 예시(가상 예시)
val userData = fetchUserData()    // 네트워크 요청 -> 여기서 작업 완료까지 멈춰 있음
processUserData(userData)
```

```kotlin
// 비동기 방식 예시(콜백 기반)
fetchUserDataAsync { userData ->
    processUserData(userData)
}
// fetchUserDataAsync가 호출된 직후에 return 돼서, 다른 코드들을 이어서 실행 가능
```

> **정리**
> - 비동기는 “결과를 기다리지 않고 곧바로 다음 작업을 수행할 수 있다”는 특징을 말합니다.
> - 비동기 작업이 끝나는 시점에 별도의 알림(콜백, 이벤트, 미래값 등)을 통해 결과를 전달받습니다.

## 3. 동시성과 비동기의 관계

- **동시성**은 여러 흐름(작업)이 서로 간섭하지 않고 “같이 실행되는(또는 번갈아가며 실행되는)” 상황을 의미합니다.
- **비동기**는 “특정 작업이 완료되기를 기다리지 않고도, 다른 작업을 계속 진행할 수 있다”는 실행 방식입니다.

이 둘은 종종 함께 사용되지만, 완전히 같은 개념은 아닙니다.

1. **비동기를 사용하면**, 기존의 코드 흐름이 “작업 완료 후에 다음 단계로”가 아니라 “일단 다른 일을 하고, 나중에 결과를 받음” 형태로 바뀝니다.
2. 이 때 여러 작업들이 “동시에” 일어날 수 있으려면(또는 동시에 처리되는 느낌을 주려면), 내부적으로 **동시성**(또는 병렬성)이 필요합니다.

즉, 비동기는 “완료 여부와 상관없이 바로 다음 일을 처리할 수 있는 구조”를 만드는 것이고, 동시성은 “실제로 여러 일을 함께(또는 번갈아가며) 수행하는 것”을 의미합니다.

## 4. 코루틴에서의 동시성과 비동기

코틀린 코루틴은 이런 동시성과 비동기 처리 방식을 **직관적인 코드 형태**로 표현하게 해줍니다.

- `launch`, `async` 등의 빌더로 **동시에 여러 코루틴**을 실행할 수 있고(= 동시성).
- `suspend` 함수를 통해 **결과를 기다리지 않고** 다른 작업을 실행하다가, 나중에 필요한 시점에 재개할 수 있습니다(= 비동기).

### 예시

```kotlin
// 코루틴 스코프
scope.launch {
    // 1) 동시 실행 (동시성)
    val data1 = async { fetchDataFromApi1() }
    val data2 = async { fetchDataFromApi2() }

    // 2) await() 통해 결과 합치기 (비동기)
    val result1 = data1.await()
    val result2 = data2.await()
    processResults(result1, result2)
}
```

1. `async { ... }` 블록이 여러 개 호출되면, **동시에** 여러 비동기 작업이 진행됩니다(코루틴 레벨에서 동시성).
2. 각 작업이 끝날 때까지 **기다렸다가**(suspend) 완료 시점에 결과를 전달받습니다(비동기).
3. 개발자는 “동기 코드처럼 순차적으로 쓰인” 이 코드를 읽으면서도, 내부적으로 동시성과 비동기가 잘 조합된 동작을 얻을 수 있습니다.

## 5. 결론

- **동시성(Concurrency)**: 여러 작업이 동시에(혹은 번갈아가며) 실행되는 형태나 개념.
- **비동기(Asynchronous)**: 작업 완료를 기다리지 않고 다음 작업을 진행하며, 후에 작업 완료 시점에 결과를 받는 실행 방식.

두 개념은 서로 밀접하게 얽혀 있지만,
- 동시성은 “작업을 병렬적으로(또는 교차적으로) 실행하는 방식”
- 비동기는 “결과를 기다리지 않고도 흐름을 이어갈 수 있는” 설계 방식

코틀린 코루틴에서는 이 두 가지가 결합되어, **직관적이면서도 효율적인 비동기 코드를 작성**할 수 있게 됩니다.
