# 6.e CPU, 코어, 스레드, 스레드 풀

CPU, 코어(Core), 스레드, 스레드 풀(Thread Pool) 사이의 관계를 이해하려면, **하드웨어 (물리적인 CPU)** 와
**소프트웨어(운영체제/프로그램 레벨에서의 스레드** 의 관점이 어떻게 다른지 살펴보는 것이 중요하다.

## 1. CPU와 멀티코어

### 1.1 CPU(중앙 처리 장치)
- 컴퓨터에서 연산을 수행하는 핵심 부품
- 이전에는 CPU가 한 번에 하나의 연산을 처리하는 단일 코어(single-core) 구조 였지만, 지금은 대부분 여러 코어를 내장한 멀티 코어 CPU를 사용한다.

### 1.2 멀티코어(Multi-Core)
- 하나의 CPU 칩 안에 독립적으로 연산을 수행할 수 있는 코어가 여러 개 들어 있다.
  - 예: 4코어 CPU라면 4개의 코어가 동시에 병렬 연산을 수행할 수 있다.
- 일부 CPU에는 하이퍼스레딩(Hyper-Threading) 같은 기술이 있어서, 논리적(가상) 코어가 물리적 코어보다 더 많은 수로 잡히기도 한다.
  - 여담으로 AMD는 이 기술을 SMT(동시 멀티스레딩)라는 명칭을 그대로 쓰지만 하이퍼스레딩이란 이름은 인텔이 붙였다고 한다. -> 요새는 안쓴다함

물리 코어가 여러 개 있으면, **동시에** 여러 개의 스레드가 실제로 **병렬 연산**을 할 수 있다.
4코어 CPU라면, 대략 **동시에** 4가지 일을 진행시킬 수 있다.(스케줄러와 OS의 작업 분배 방식에 따라 다름)
동시에라는 말은 동시성과는 다른 말이다.

## 2. 운영체제 레벨의 스레드(Thread)

### 2.1 스레드
- 프로세스(프로그램 실행 단위) 내에서 실제 연산을 수행하는 실행 흐름(flow of execution)
- 한 프로세스가 여러 스레드를 만들면, 각 스레드가 CPU 시간을 분할해서(또는 병렬) 돌아가며 코드를 수행한다.

### 2.2 스레드와 CPU 코어의 관계 
- 스레드가 많다고 해서 동시에 모두가 "물리적인 CPU 코어"를 점유하는 것은 아니다.
- 운영체제의 스케줄러가 여러 스레드를 CPU 코어에 할당시키면서 실행된다.
- 만일 4코어 시스템에서 8개의 스레드가 동시에 대기한다면, 실제로는 각 코어가 순차적으로 스레드들을 번갈아 실행하거나, 4개는 동시 실행 중이고 나머지는 대기 상태일 수 있다.

## 3. 스레드 풀(Thread Pool)

### 3.1 개념
- 스레드를 미리 생성해두고 재사용하는 기술이다.
- 프로그램(서버, 코루틴 디스패처, 자바 ExecutorService 등) 에서 요청이 들어올 때마다 새 스레드를 만들지 않고, 풀에 있는 스레드를 가져와 작업을 수행한 뒤 다시 돌려놓는다.
- 스레드 생성/제거가 잦으면 오버헤드가 크다. 그래서 보통 일정 개수의 스레드를 "풀"로 묶어두고 재사용해 효율을 높인다.

### 3.2 풀의 크기 결정
- CPU 바운드 작업이 많은 경우, 코어 수와 비슷한 스레드 수가 보통 효율적이다.
  - 코어는 4개인데 스레드를 100개 만들면, 실제로 동시 병렬 처리되는 건 4개 뿐이고, 오히려 Context Switching 때문에 오버헤드가 커질 수 있다.
- 블로킹 I/O가 많은 경우, 작업이 파일/네트워크를 기다리는 동안 CPU가 쉬게 되므로, 더 많은 스레드를 사용해도 효율이 올라갈 수 있다.
  - I/O 대기 중인 스레드가 있다면, 다른 스레드를 CPU에 할당해 쉴 새 없이 작업을 진행할 수 있다.
